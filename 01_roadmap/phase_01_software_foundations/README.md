Phase One establishes the foundational programming knowledge required for my Python Backend Engineering roadmap.

The phase focuses on building a strong foundation in Python programming, problem-solving, basic algorithmic thinking, software requirements, and practical application through exercises, source code, and foundational testing practice.

The repository separates learning documentation, source code, and testing work into complementary areas, allowing each to be maintained and expanded independently while preserving the relationship between them.

## Phase Status

Phase One has been completed through a structured learning sequence. The repository contains the resources, practical work, study notes, documentation, testing practice, and learning artifacts actually produced during the phase.

## Learning Order

The resources in this phase were studied in the following order:

1. **Python Crash Course** — Part I: Basics, providing foundational Python knowledge and practical exercises.
2. **Learn to Code by Solving Problems** — programming fundamentals, problem solving, algorithmic thinking, and introductory Big O.
3. **Software Requirements** — Chapters 1–2, introducing software requirements fundamentals and requirements documentation.

Although *Python Crash Course* and *Learn to Code* were studied partly in parallel, the learning sequence followed a chapter-by-chapter approach where the corresponding chapter from *Python Crash Course* was studied first, followed by the corresponding chapter from *Learn to Code*, when applicable.

## Learning Approach

Phase One is designed around progressive learning rather than simply completing resources.

Foundational concepts are introduced, practiced, and documented before being revisited at greater depth later in the roadmap.

The code, documentation, and testing work are therefore preserved as a record of the learning progression. They are not intended to represent final production-level implementations or comprehensive mastery of every topic introduced during the phase.

As the roadmap progresses, programming practices, testing, documentation, software design, and overall engineering quality will become increasingly rigorous.

## Repository Organization

The phase is divided into three complementary areas:

- **[`docs/`](./docs/README.md)** — study notes, explanations, and learning documentation.
- **[`src/`](./src/README.md)** — source code, exercises, solutions, and practical implementations.
- **[`tests/`](./tests/README.md)** — testing practice and test-related learning artifacts produced during the phase.

Resource-level `README.md` files connect the documentation with the corresponding practical work, while the `tests/` directory preserves the testing work associated with the learning process.

## Testing in Phase One

Testing was introduced during Phase One as a foundational topic rather than as a fully developed testing discipline.

Early in the learning process, some test files were created as part of initial practice and experimentation. As the study progressed, testing was approached more deliberately, with the understanding that effective testing requires learning and understanding testing concepts before relying on repeated practice alone.

As a result, some test files in `tests/` contain limited or incomplete test implementations. Their presence documents the actual learning process and should not be interpreted as evidence of comprehensive testing experience or mastery.

More systematic testing practices, test design, fixtures, mocking, coverage, and professional testing workflows will be developed in later stages of the roadmap.
