## Organization

The source code is organized by learning resource rather than by programming topic.

Each resource has its own directory containing the practical work produced during the corresponding study period.

Where applicable, resource-level `README.md` files provide additional information about the organization of the code, exercises, and the relationship between the source code and the corresponding study notes.

## Learning Philosophy

The code preserved in this directory represents practical work produced during the learning process.

The purpose of this directory is to document the progression from studying concepts to applying them through code and exercises. The code therefore reflects the learning stage at which it was produced rather than attempting to present every exercise as polished production software.

Code quality, organization, documentation, testing practices, and software engineering techniques are expected to improve progressively throughout the roadmap.

## Relationship to Documentation

The source code and study documentation are intentionally maintained separately:

* **`docs/`** contains study notes, explanations, and learning documentation.
* **`src/`** contains source code, exercises, and practical implementations.

The two directories are connected through their respective resource-level `README.md` files, allowing the learning material and the resulting practical work to be navigated together.

## Phase One Scope

This directory reflects the practical work actually produced during Phase One.

It does not include resources or work that belong to later phases. In particular, material from later parts of a resource is not moved into Phase One simply for organizational consistency.
