## 🎯 Learning Focus

The main learning track is **Python Backend Engineering**, supported by a strong foundation in **Software Engineering**.

Additional areas such as **AI / LLM Engineering** and **Data Analysis** are treated as **side tracks and supporting skills**, not as separate primary career paths.

They will be introduced progressively when they become relevant to the main learning path and when time and capacity allow.

The goal is to build a strong and coherent backend engineering foundation while developing practical supporting skills in AI and Data Analysis, without turning them into competing learning tracks or creating unnecessary workload.

## 📖 Learning Resources & Depth

The presence of a topic in an early resource does not mean that the topic has been fully mastered or that the resource represents its final treatment.

For example:

* **Python Crash Course** provides foundational exposure to topics such as OOP and Testing.
* **Learn to Code** introduces algorithmic thinking and Big O notation.
* These topics will be revisited and studied more deeply as the roadmap progresses.

The learning strategy is therefore based on **progressive depth** rather than attempting to master every subject from its first introduction.

## 💻 Code & Learning Transparency

The code preserved in this repository represents the stage at which it was produced.

It is not intended to present every exercise as polished production software.

Some early exercises contain:

* Commented-out solutions
* Multiple solution approaches
* Earlier attempts
* Limited comments or explanations

These are preserved intentionally when they provide useful context about the learning process.

The repository is not retrospectively cleaned into an artificial representation of a more advanced skill level.

### Learn to Code — Solution Transparency

The solutions stored for *Learn to Code by Solving Problems* are complete final solutions kept in the repository, and some problems contain multiple approaches.

However, their presence should **not** be interpreted as evidence that every problem was solved completely and independently from scratch during the original study.

My ability varied from problem to problem. Some problems could only be partially solved independently, while others could be solved substantially or almost completely.

The stored solutions therefore represent the **final learning artifacts**, not a measurement of independent problem-solving ability at the time.

This distinction is intentional and exists to preserve an accurate and transparent record of the learning process.

## 🚀 Learning Philosophy

The journey follows several principles:

* **Mastery before progression** — understand and apply concepts before moving forward.
* **Application over passive consumption** — use projects and exercises to reinforce learning.
* **Progressive depth** — revisit important topics at increasingly advanced levels.
* **Resource ≠ Work** — clearly distinguish learning sources from produced artifacts.
* **No unnecessary repetition** — use resources because they add value, not simply to collect more material.
* **Learning history matters** — preserve meaningful evidence of progression rather than rewriting the past.
* **One coherent main track** — keep Python Backend Engineering and Software Engineering as the central direction while allowing supporting skills to develop around them.
